# Hermes Android 3.7.7

本次交付同签名安装包及完整源码。389 项 Android 自动化测试通过，发布 Lint 零错误，APK 签名与 ZIP 对齐校验通过。完整验证范围见 VALIDATION-3.7.7.md。

## 改动及目的

- 统一首页的圆角卡片、字体层级和间距；分类改为文字标签加选中下划线。普通说明、数字指标、记录和 20 种交互各有对应显示内容，减少背景长文与 facts 的重复。
- presentation_version 升至 3。每张卡必须明确 layout 和 caption；decision/followup 必须提供合法 interaction。旧 JSON 可以继续读，但 App 提示升级，写入工具的正常入口不再接受缺少交互字段的旧格式。
- 内容规则要求交代对象、背景、现状和待回应事项，区分来源日期与事实发生日期。找不到后续记录只表示待核对，不得推断仍未完成；不把脚本修复日志和资料缺失报告堆成首页事项。
- 卡片提交在首页发起后台对话，保留具体输入和操作编号，显示核对中、处理中、未确认及服务器确认结果。对话中的一句“已完成”不算成功，以 JSON 中同一操作编号的写回回执为准；不自动重放结果不明的操作。
- 同工作区多张卡片共享短时结果读取，手机退到后台时暂停卡片轮询。刷新后如卡片结构变化，旧输入保留但不再按过期字段提交。
- 早晚配置仍由 Hermes 执行。附带规范、脚本、例子和模板，保存到已验证工作区；匹配唯一任务则更新，缺少则创建，保留无关任务。settings.json 记录真实任务 ID。App 可按 ID 从 Cron API 核对启用状态、工作区规则和服务器返回的下次运行时间。
- 心跳超时从实际探测开始计时；后台暂停或计时回调延迟后重新探测。连接诊断按服务器和账号保留最近 40 条简化记录，便于追查偶发故障。
- JSON 写入仍有哈希冲突检查、原子替换、备份、回读及操作去重；候选内容不能伪造回执，日常整理不能重开已关闭卡片。

## 安装与配置

1. 使用 Hermes-Android-3.7.7-release.apk 直接覆盖安装，保留原有 App 和连接配置。
2. 首页菜单进入“早晚整理”，确认早晚时间及设备时区，再交给 Hermes 配置。这一步迁移旧卡片并创建缺失的对应任务，不需手工 SSH 修改文件。
3. 等配置对话结束，回到早晚整理，点击“核对已配置的任务”，看到真实早晚任务 ID、启用核验和下次运行时间。
4. 同步首页后，选择一张简单确认卡试用。提交后留在卡片看结果；复杂澄清或排查可打开处理详情。
5. 如仍断线，提供诊断页最近的连接记录及当时是否刚解锁手机/切换网络。此版本的代码修复不等于已经证明真实服务器上的所有断线原因。

服务器仍使用用户自己的 Hermes、工作区 JSON 和 Markdown。此开发过程没有访问或修改真实服务器任务及业务档案。签名密钥和用户上传的实际数据不包含在源码包中。
