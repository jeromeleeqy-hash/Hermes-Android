# Hermes Android 3.8.3

日期：2026-10-05。基于用户提供的完整 3.8.2 源码，包名保持 `com.qingyu.hermescompanion.preview`，versionCode 为 383。

## 本次修复

1. 底部圆角提示条使用与液态玻璃导航栏一致的 16dp 水平间距，去掉 Snackbar 默认容器造成的额外缩进。保留长文本换行和横向系统安全区。
2. 概览统一收纳至 `.hermes-app/today/`。App、writer、规范、Cron 模板与设置核验同步更新；尚未迁移的工作区仍可读取和写入根目录版本。
3. “结果待核对”先打开处理详情并核对回执，不再直接跳到已失效的处理对话。“继续未完成部分”对加载中、等待审批、原任务未确认停止、网络失败等情况给出反馈。原对话确认不存在时沿用原 operation_id 创建核对会话，只在原记录足以证明完成时补齐卡片和回执；证据不足时询问，避免重做旧任务。
4. 首页刷新图标自动发起一次概览整理：带入当前 Profile、工作区内有限的最近对话，优先采用用户明确报告的进展和完成状态。显示读取、整理、待确认或失败状态，并提供“查看处理”。以本次 refresh_id 对应的服务器回执判断写回完成，不能把 Agent 一句“完成”或文件时间变化当作成功。

## 文件位置

| 内容 | 原位置 | 收纳后 |
| --- | --- | --- |
| 概览 | `hermes-today.json` | `.hermes-app/today/hermes-today.json` |
| 协作锁 | `.hermes-today.lock` | `.hermes-app/today/.hermes-today.lock` |
| 概览快照 | `.snapshots/hermes-today/` | `.hermes-app/today/snapshots/` |

业务 Markdown 及其相对路径仍以工作区为准。`.snapshots` 中其他程序的内容不迁移；目录完全为空才清理。新旧概览不同、快照同名不同内容或锁被占用时中止迁移并保留资料。先备份、复制、校验和记录迁移回执，再清理旧文件；中断后可重跑。

安装后从“首页 → ⋯ → 收纳首页文件”启动迁移。该会话会安装本版附件，并核对、暂停和更新确实匹配的概览 Cron，保留任务 ID、时间、时区、投递方式及原启用状态。没有匹配 Cron 可以只迁移文件；有歧义时报告，不猜任务、不创建重复任务。安装 APK 本身不会操作服务器。

## 刷新和恢复的边界

- 首页图标会调用 Hermes 整理概览，可能需要等待模型与服务器处理。“首页 → ⋯ → 仅同步已保存的概览”仍是只读同步；前台定时同步和对话完成后的同步也是只读操作。
- 最近对话最多选择 6 个，每个取最近一页中最多 16 条用户或助手正文，不采集工具和系统消息；已知其他 Profile 或工作区的会话不参与。过长消息会标记截断，读取失败会保留未覆盖提示，因此不声称检查了全部聊天历史。
- 刷新只更新概览，不重做聊天中的任务，不修改原业务记录或 Cron。刷新回执与卡片动作回执独立。
- 恢复操作先读当前记录与原回执；不绕过服务器审批，网络失败不等于原会话已丢失。原任务是否结束无法确认时提示等待，不自动重发。
- 保留既有 action_receipts、已完成状态、稳定卡片 ID、私有加密缓存、应用更新及三套外观。

实际构建与验证结果见 [VALIDATION-3.8.3.md](../../VALIDATION-3.8.3.md)。本开发环境没有连接用户的 Hermes 服务器，迁移和真实聊天更新需在安装后验收。
