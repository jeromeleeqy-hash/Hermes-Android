# Hermes 3.0.4 修复说明

本次针对社交媒体用户反馈的「项目目录未跟随新会话」和「不同会话无法同时运行」修复。

## 使用变化

- 在会话页选择项目后，新建对话会绑定该项目的服务器目录；创建项目成功后自动选中它。
- 切换项目时显示该项目的会话，打开历史会话继续使用它自己的目录。历史内容不会因筛选项目而被搬到其他项目；如需迁移，使用「移至项目」。
- 对话顶部显示当前项目或目录。聊天入口打开工作空间时，也进入对应目录。
- A 对话运行时可新建或打开 B 对话继续提问。任务页逐项显示运行中的会话，可分别打开或停止。
- 回复、工具状态、草稿、附件、失败重试、排队消息与断线恢复记录按会话隔离。后台会话失败不会覆盖当前输入。
- 停止 A 不影响 B。A 的停止请求处理完毕后再允许 A 开始下一轮，防止迟到的停止请求误停新任务。
- 运行中的会话暂不允许移动目录、归档或删除；停止后即可操作。Profile 切换仍需等待当前 Profile 的任务结束。

## 技术修复

1. 新建对话将所选目录交给 `session.cwd.set`；恢复历史对话后，在提交提示词之前重新绑定会话目录。目录绑定失败时终止提交，不静默使用默认目录。全程不修改网关全局活动项目。
2. WebSocket 注册从单一 `activeStream` 改为按运行会话 ID 存放的并发映射。已知 ID 严格匹配；多个运行并存时忽略无法确定归属的无 ID 事件。
3. ViewModel 按 Profile 与持久化会话 ID 保存独立运行对象；延迟回调只有在原运行对象仍有效时才会处理，旧回调不会结束新运行。
4. 恢复连接时复用健康连接，避免一个会话的恢复打断其他会话。兼容读取 3.0.3a 的单任务快照。
5. 项目目录匹配优先采用最长路径，防止父项目抢占子项目会话，并正确保留根目录 `/`。

## 构建与签名

版本为 `3.0.4-release`，versionCode 为 `305`，正式 applicationId 保持 `com.qingyu.hermescompanion`。

你提供的源码 ZIP 不包含 `signing/hermes-debug.keystore`。要生成能够覆盖已发布版本的安装包，请将**原来发布时使用的签名文件**放回这个位置，或沿用原有发布环境的签名配置。

不要生成一个新密钥替代旧签名来发布覆盖升级，也无需先卸载已安装 App。未放入签名文件时，`assembleRelease` 只会输出未签名 APK，不能直接安装。

Mac / Linux（Android SDK 已就绪）：

```bash
chmod +x gradlew
./gradlew testReleaseUnitTest assembleRelease
```

Windows：

```bat
gradlew.bat testReleaseUnitTest assembleRelease
```

构建产物位于 `app/build/outputs/apk/release/`。

## 真机验收步骤

1. 创建两个不同目录的项目 A / B。分别选中项目并新建对话，询问当前工作目录或让 Agent 执行 `pwd`，核对实际路径。
2. 在 A 发起耗时任务，切换 B 后继续提问。来回切换，确认回复和工具状态各自保留。
3. 两段对话都在运行时停止 A，确认 B 继续；等 A 停止完成后再发一条消息。
4. 两段对话分别排队一条消息，确认各自在本轮结束后发送。
5. 在 B 输入未发送草稿，制造 A 的发送失败，确认 B 草稿保留，A 可以找到原内容重试。
6. 断网后重连或重新启动 App，检查多会话的结果恢复及审批请求；这一项需结合实际部署的 Gateway 验收。

本次没有修改、更新或重启你的服务器，也没有上传到 GitHub 或对外发布。
