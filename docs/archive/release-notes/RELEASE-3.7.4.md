# Hermes Android 3.7.4 · 交互卡片试用版

基于本地 3.7.3 代码与 20 类卡片设计实现。使用既有 Hermes 网关，服务端继续使用工作区 Markdown 与 hermes-today.json；无需部署新数据库、新服务或第二个 Agent。

## 可以试什么

- “今日 → 卡片体验 · 20种”：离线示例画廊，支持选择、勾选、排序、表单和分拣。操作只留在演示界面，绝不发送到 Hermes，也不写真实概览。
- 真实首页按交互类型呈现短信息，长背景和来源默认折叠。详情的主要按钮固定在底部，支持现有三种皮肤、深浅色与系统字号。
- “升级交互卡片 · 不查历史”：将当前协议、校验脚本和示例带入新对话。发送后要求 Hermes 仅转换已有 JSON，不扫描历史，不复制示例任务，不修改事实及日期。
- “早晚整理”：选择两次 HH:mm 时间及 IANA 时区，点击“交给 Hermes 配置”会发送配置请求。Hermes 将实际附件保存到当前工作区 .hermes-app/today/，核对并复用/创建对应 Cron，持久化真实任务 ID；每个新 Cron 对话显式加载相同规范。是否成功以处理对话中的核验结果为准。
- 真实卡片的选取和填写是本地草稿；点击主按钮后先重读当前 Profile 的服务器概览。卡片或工作区发生变化时拦截提交。通过核对后打开处理对话，自动发送结构化选择及操作编号。

## 20 类的实际操作

| 类型 | 本版交互 |
|---|---|
| 澄清确认 clarification | 选关联、分开或不确定；不隐式结案 |
| 方案比较 comparison | 并列比较，采用一个方向 |
| 重点排序 priorities | 上下移动并提交顺序 |
| 时间选择 time_picker | 候选时段与时长，准备安排草稿 |
| 会议分工 meeting_actions | 选择事项，校正负责人和截止日，建立个人跟踪 |
| 待办清单 checklist | 勾选本次确认完成的步骤 |
| 阶段验收 milestones | 核对阶段与验收条件后提交 |
| 阻塞处理 blocker | 填写缺失信息，交给 Hermes 核实 |
| 执行状态 execution | 查看最近记录的阶段，请求核对实际进度 |
| 成果验收 deliverable | 采用版本或填写修改要求 |
| 数据趋势 metrics | 主数值、真实趋势点，请求分析 |
| 变化提醒 change | 对照前后值，接受变化或保留原计划 |
| 事件轨迹 timeline | 选看节点，补充事实 |
| 依据核验 evidence | 切换已有依据/待核验项，发起核验 |
| 文稿修订 revision | 逐条选择建议，保存为新版本 |
| 资料分拣 triage | 按资料选择归档、任务线索或稍后处理 |
| 记忆校正 memory_change | 对照变更，纠正或撤销指定记忆 |
| 人物跟进 person_followup | 基于已有交集准备跟进草稿 |
| 快速记录 quick_log | 数字、文字、日期、时间及选择字段 |
| 晚间复盘 reflection | 查看完成数量，选择明日重点并记心得 |

外发消息、邀请、支付、删除不属于普通卡片操作。执行卡本版没有通用暂停/继续，也不生成虚假百分比。人物卡仅准备草稿。

## 数据与兼容

schema_version 保持 1，新增 presentation_version=2 与可选 presentation.interaction。旧版卡片可继续阅读；未知/不合法交互类型回退旧展示，并保留原始数据供修复。展示标题、列表长度、字段类型与合法值在客户端及 Python 校验器中检查。

服务端仍是正式记录。手机继承 3.7.3 的私有 AES-GCM 加密缓存，前台约每 45 秒、恢复前台和对话完成时检查服务器。离线或强制停止后下次连接补同步；缓存不是完整文件备份，也不是即时后台推送。

提交前客户端核对当前卡片，Agent 写入时仍需核对文件哈希。writer 使用协作锁、快照和原子替换，保存最近 200 次操作回执并识别相同操作编号重试；普通 Cron 更新保留这些回执。校验器禁止将 example_only 示例文件直接覆盖真实概览。

## 试用边界

- 表单通过 Hermes 处理，未实现绕过模型的即时原记录写入。写入结果在处理对话中展示，再同步回首页。
- App 核对与脚本约束不能保证 Agent 始终遵守指令。Markdown 与 JSON 暂无跨文件原子事务，需先保存原记录再更新概览；中途失败必须说明和恢复。
- 卡片表单采用界面状态恢复，未建立可跨设备同步的离线提交队列；退出或刷新卡片前请完成提交。
- Cron 创建、修改和时区核验需要现有 Hermes 能力，由配置对话实际执行。本次开发没有连接用户的真实服务器，也没有安装或开启任务。
- 同一概览最多 200 张卡、1 MiB。采用稳定 ID 更新同一事项；超过容量要明确安排归档，不无限追加重复日报。
- 增量整理限定相关资料读取范围，但尚无用户服务器上的实测延迟，不承诺固定秒数。

## 构建

JDK 21，Android SDK 36 / build-tools 36.0.0，仓库 Gradle wrapper。`hermesPreview=true` 保持交付包应用 ID。通过 `hermesSigningFile` 指定签名文件，源码不包含私钥、local.properties、凭据或私有记录。

建议运行 `python3 -m unittest discover -s tools -p 'test_today_writer.py'` 与 Gradle `:app:testDebugUnitTest :app:lintRelease :app:assembleRelease`。离线 Robolectric 需本地准备对应 SDK 测试依赖；具体结果见 VALIDATION-3.7.4.md。
