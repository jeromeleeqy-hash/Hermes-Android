# Hermes Android 3.8.0

本次围绕“了解用户、把值得关注的事讲清楚、主要通过聊天协作”调整已有客户端。沿用自部署 Hermes、JSON、Markdown 和早晚 Cron，不增加数据库或第二个 Agent。

## 页面变化

| 页面 | 新的呈现方式 |
| --- | --- |
| 首页 | 关注中、待收尾、提醒你；每张卡先说明事情与现状。摘要、已记录步骤、真实日程和数据按内容呈现，聊天是主要入口。 |
| 事项详情 | 阅读在前；背景和来源按需展开。旧卡的快捷回应仍可单独打开，未完成操作与审批没有被移除。 |
| 对话 | 保持现有结果阅读方式。“参考资料”只收集当前轮次、去重后默认折叠；工具过程放进“处理详情”。内部概览配置附件收成“已带上相关背景”，可展开移除。 |
| 文件 | 直接浏览工作区，移除“最近产物”及页面切换。保留文件预览、编辑、分享和选为附件。 |
| 任务 | 当前、定时、记录三个入口。定时卡只显示名称、简洁时间、状态与开关；详情、立即运行和删除放入菜单。 |

首页默认不因为卡片种类为 decision 就自动置顶，优先采用 Agent 有依据的关注优先级，保持同级事项的原始顺序。关闭事项默认不显示；阅读、滚动与打开详情不会改变业务状态。

## 如何让服务器采用新规则

安装客户端后，旧 JSON 会兼容显示。要同时改善内容生成，在首页右上角菜单选择“调整首页整理方式”。App 将本次规范、writer、示例与一次性请求发给 Hermes。

该操作要求 Hermes：

- 依据明确偏好、近期重点与相关事实选择事项；不把历史目录推断成当前目标，不把未知进展写成持续逾期。
- 更新为 presentation_version 4 / editorial_version 2；待决定、待跟进允许只读卡片，交互是可选项。
- 简洁表达保留对象、背景与现状，处理日志不进入事项卡和默认回复。
- 更新能够核实匹配的已有概览 Cron 和持久规范，保留任务 ID、时间、时区及启用状态；找不到或有歧义不自动新建。
- 校验、按旧哈希合并写入并回读，保留来源、稳定 ID、完成状态与动作回执。

新安装且从未配置过概览的用户，仍使用“早晚整理”选择时间并配置。不要为了升级再次创建一套早晚任务。

## 对旧操作中断的处理

继续使用原选择与原 operation_id，只补原动作欠缺的部分。若后续概览已经吸收了原确认，应保留新版卡片并核对原动作回执，不把旧候选覆盖回来。新的问题、新的选择不能复用旧 operation_id。真正的事实冲突仍需说明并确认。

writer 保留并发版本校验、协作锁、原子文件替换、快照、已关闭卡保护及幂等回执。Markdown 与 JSON 之间仍没有跨文件事务；客户端不把聊天里的“完成”当作回执。所有实际审批继续遵守 Hermes 服务器规则。

## 本次边界

这是客户端与随附规则的升级，并未远程安装到用户服务器，也未自动整理用户记忆。Hermes 是否熟悉用户，仍取决于已有可靠记录、明确反馈以及后续使用；新版规则改善的是读取和表达方式，不能保证模型每次都提炼正确。

保留 3.7.8 的网关、审批和断线恢复。本次去掉进入文件页时的额外最近产物扫描，但没有访问用户的真实 9119 服务或手机网络，不能据此宣称网络问题已经消失。
