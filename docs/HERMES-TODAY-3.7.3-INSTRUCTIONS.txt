Hermes App 3.7.3：转发给 Hermes 的指令

推荐用法
1. 更新 App 后打开“今日”，先同步一次已有概览。
2. 对仍有长摘要的卡片，点“整理卡片 · 不查历史”。新对话草稿会自动附带完整规范和实际校验脚本，确认后发送。
3. 需要新信息时使用“查找新变化”。右上角同步只读取已有 JSON，不让 Agent 重做总结。
4. 如果通过其他 Hermes 入口发送，请同时附上本包的 hermes-today-contract.md 和 hermes-today-writer.py，然后复制以下指令。不要只转发一个服务器上并不存在的脚本路径。

——可转发正文——

请按附件 hermes-today-contract.md 3.7.3 版规范执行一次 compact_existing_only：仅把现有今日概览整理成适合手机交互的卡片。

先核实我当前 Profile 对应的 App 工作区，以及其中已有的读写规范；不要写死历史消息中的 /root/workspace。使用根目录的 hermes-today.json，读取时立即记录 SHA-256。

本次只读取规范和已有 JSON，不重新总结历史、不全盘扫描、不修改 MEMORY.md、人物档案、时间线、待办、Cron 或其他业务记录，不安装新环境、数据库或 Skill。

一张卡只保留一件事或一个问题。标题建议 12–24 字、最多 48 字；摘要建议一句 30–60 字、最多 160 字。问题放 presentation.question，关键事实最多三条放 facts，具体回答入口放 options，旧的长摘要原文放 background。事实待确认用 intent=clarify，真正要求我作选择用 intent=decide。不要虚构选项依据、指标、负责人、日期或进度。

保留事实、来源、状态、信息日期和 generated_at。拆卡时主事项保留原 id，其余使用稳定衍生 id；无法判断是否同一件事时留给我确认。schema_version 保持 1，全部卡片通过新限制后增加 presentation_version: 1。

使用附件里的完整 hermes-today-writer.py，在临时目录保存脚本和候选 JSON，以最初记录的 SHA-256 做并发校验，通过后保存快照并原子替换；再回读核验。没有脚本附件或校验失败时说明原因，不编造“校验通过”。

完成后只回复：实际保存路径、卡片数、校验与回读结果、未解决的问题，不再贴整份长摘要。手机会自动检查服务器文件，不需要你另发一份 JSON 到手机。

——正文结束——

日常更新规则
“查找新变化”请求会自动附上 refresh_overview_only 模式。它要求先用现有概览和最近摘要，只增量读取变化的相关资料，默认最多 8 份新正文、约 20000 字；超出或缺失范围写入 coverage_note，不能冒充全量完成。
这只是读取与写入规范，不意味着脚本已永久安装，也不自动改造现有 Cron。若要接入早晚总结，应在确认原任务后让它引用同一份规范，不再创建重复任务。

手机副本的范围
服务器保留正式 JSON；手机在私有、禁止系统备份的目录保存 AES-GCM 加密副本，密钥由 Android Keystore 管理。按服务器、账号、Profile 隔离，已确认工作区改变时不沿用旧区数据。退出连接会清理概览副本。
App 前台约每 45 秒、恢复前台及对话完成时检查更新；同步期间不调用模型，内容不变不重复写缓存。断网或关闭 App 时，下一次连接再补同步，并显示本地副本及上次同步时间。本版没有服务器主动推送，也没有完整 Markdown/附件离线镜像。
新 JSON 无效或暂时读不到时，保留同一工作区的上次内容并提示；本地副本不能替代服务器备份。

关于速度
缓存缩短打开和浏览等待；增量规范减少重复读资料，但模型推理、外部工具和网络仍可能慢。此版本要求 Hermes 简报实际读取文件数和约字数，可测量时再报告阶段耗时；没有你的运行日志，不能确认实际瓶颈或承诺固定秒数。
