# Hermes UI 2.0 视觉与交互规范

## 核心语气

Hermes 是工作终端，不是功能陈列柜。视觉表达遵循“内容 > 状态 > 容器 > 装饰”：先保证标题、正文和操作路径，再用少量颜色与形状建立识别。

## 单一界面体系

- 只维护一套 Telegram 式清爽办公界面，不再提供液态玻璃皮肤切换。
- 中性浅灰页面承载纯白内容表面，标题和正文保持高可读性。
- 列表、导航和筛选默认平铺；仅选中项和主要动作使用低饱和蓝色。
- 图标通常无底板，连续列表不拆成多张小卡片，分组依靠间距和细分割线。
- 视觉材质必须服从信息层级，不以模糊、光晕或多层圆角制造设计感。

## 基础令牌

| 角色 | 规范 |
| --- | --- |
| 分组圆角 | 16 dp |
| 控件圆角 | 12–16 dp |
| 菜单圆角 | 14 dp |
| 面板阴影 | 默认 0 dp，浮动操作与底栏可使用轻阴影 |
| 图标底板 | 只用于需要语义识别的设置入口和状态 |
| 选中填充 | 低透明主色容器 |
| 紧凑触控区 | 不小于 44 dp |

## 字体层级

- 一级页面标题：19 sp / 25 sp，SemiBold。
- 行标题与关键控件：13.5–15.5 sp，Medium 或 SemiBold。
- 正文：13.5–15 sp，Normal。
- 辅助信息：10.75–12 sp，Normal 或 Medium。
- 禁止同时通过“大字号 + 粗体 + 高饱和色 + 色块”重复强调同一信息。

## 容器规则

- 页面背景不算卡片；主内容不需要再套一层大卡片。
- 同一连续列表使用一个分组表面或直接平铺，不为每一行单独画卡片。
- 弹层应比页面内容高一个层级，不能比主任务更抢眼。
- 菜单文字使用 `labelLarge`，视觉行高紧凑，但点击区保持至少 44 dp。

## 深色模式

- 标题和正文只能使用 `onBackground` / `onSurface` 语义色，不硬编码黑色。
- 辅助文字使用 `onSurfaceVariant`，禁用态再降低透明度。
- 深色内容表面使用 `surface`，描边不得使用纯白实线。
- 错误、成功、警告均使用对应容器色及其 on-color，避免只靠红绿区分。
