# Hermes Android 3.0.0 交接状态

## 当前基线

- 交付版本：`3.0.0-release (300)`；Debug 构建追加 `-debug`
- 最低 Android：8.0（API 26）
- 目标 Android：16（API 36）
- 当前验证重点设备：OnePlus PLZ110 / Android 16
- 构建形态：固定开发签名、R8、单 DEX Debug APK

## 已完成能力

- 远程 Hermes Gateway 用户名密码登录、Cookie 加密保存和自动恢复。
- 最近会话、项目分组、新建、搜索、AI 重命名、置顶、归档、删除和移至项目。
- WebSocket 流式聊天、静默流服务端自检、断线结果取回、停止生成和任务页工具状态摘要。
- 离开聊天后后台继续生成；完成通知、会话未读红点和底栏对话角标。
- 图片与常见附件、单次语音输入、连续语音、中文转写繁简归一化、`/` 命令提示和会话模型切换。
- Hermes 项目空间、Markdown 预览、可视化编辑和远程保存。
- 聊天 Markdown 文档卡、`@image:` 内联图片、全屏图片缩放以及返回原对话。
- 定时任务的创建、查看、修改、启停、立即执行和删除。
- 模型、对话风格、审批、记忆、Skills、工具集、MCP、通知，以及按 Profile 保存的 STT/TTS 模型设置和测试。
- 浅色、深色、跟随系统；统一使用 Telegram 式清爽办公界面，不再区分双皮肤。
- UI 2.0 已全量落地：设计令牌、字体层级、菜单密度、会话与聊天、空间与任务、底部导航、我的、网关、语音和全部设置页已统一。
- UI 2.4 已将完成状态收敛为单行提示，统一首页菜单字号，并把“我的”重建为个人主页、独立设置列表、照片裁剪/沉浸式查看和使用说明。
- Hermes Light 多色图标体系、用户与 Hermes 独立自定义头像及内置默认头像。
- 启动期崩溃捕获和应用内诊断报告。
- Profile 列表、切换与本机持久化；各 Profile 的请求、消息缓存和未读标记互相隔离。
- 审批与澄清请求加密保存；进程重启或实时连接中断后仍可响应，并继续自动取回本轮结果。
- “我的”使用我的记忆 / 我的心智入口和清晰沉浸式头像；照片区域支持上滑返回，Cron 会话统一在任务执行中心查看。

## 3.0.0 最近修改

- 连续语音改为完整柔光环、玻璃层和七段真实音量声波组成的声能核心，移除传统麦克风、断裂弧线与装饰圆点。
- 声能核心按聆听、识别、思考、回答和错误状态切换语义色与平滑波形；无声音时保持低位。
- 应用内更新记录收敛为 2.0 和 3.0 两个主要版本节点，不再逐条展示小版本修复。
- 3.0 汇总 2.0–3.0 的重要体验升级；2.0 汇总 1.0–2.0 的核心基础能力。
- 构建版本、应用内版本、README、交接文档与网络 User-Agent 统一升级至 3.0.0。

## 0.8 基线能力

- 未发送文字草稿按 Profile 和会话独立保存，发送成功后清理，退出、切换或重启后可恢复。
- 发送失败恢复文字和附件，并提供一键重新发送；无回复的乐观消息会被移除，避免重试重复。
- 长会话增加“跳到底部”，流式回复只在用户靠近底部时自动跟随。
- 会话首页增加当前 Profile、项目和时间组合筛选。
- Profile 切换状态更明确；空列表、当前 Profile 被删除等异常会安全回退。
- 用户头像和 Hermes 头像新增保存前裁剪，可调缩放及水平、垂直位置。
- 本机设置读取增加坏数据兜底，继续保留安全头像存储、启动崩溃报告、固定签名和单 DEX。
- 本版本明确暂不实现消息正文全文搜索和长回复过程折叠。

## 已知边界

- 当前 APK 是内部测试 Debug 包，不是应用商店 Release 包。
- 当前没有厂商云推送；系统完全杀死进程后，实时消息完成通知受 Android 后台限制。
- Android 12 及以上必须存在系统启动窗口，只能弱化，不能真正删除。
- 自定义头像仅保存在当前设备应用私有目录，不会同步到网关或其他设备；卸载应用会同时删除。
- Markdown 支持常见表格，不支持 HTML 表格、合并单元格和完整浏览器 CSS。
- 非 Markdown 办公文档仍以附件发送或交由其他应用处理，不提供完整原生编辑。
- 网关必须允许 `/api/files/read` 读取消息中引用的图片路径，才能显示 `@image:` 缩略图。
- 公网 IP + 端口可继续使用 HTTP，但存在明文风险；推荐通过域名、反向代理和证书启用 HTTPS。

## 接手时不要回退的决策

1. 不恢复清爽办公与液态玻璃双皮肤；长列表、正文与嵌套内容保持平铺，只在必要分组和浮动操作使用容器。
2. 不恢复厚重线性图标；继续使用轻量、多色、少装饰的 Hermes Light 图标。
3. 不得长期保存或直接渲染系统相册 `content://` URI；只能先复制到应用私有目录，再读取私有文件。
4. 不把流式请求放进聊天页面生命周期。
5. 不取消 Debug 固定签名或单 DEX，除非同时解决覆盖安装和目标设备启动兼容。
6. 不让从聊天打开的文档关闭后停留在空间页。

## 建议的下一步

1. 在真实网关上回归多张 `@image:` 图片的加载速度、失败占位和大图内存占用。
2. 为聊天图片增加压缩后的服务端缩略图接口，避免直接下载超大原图。
3. 为聊天滚动位置增加显式保存，确保预览返回后严格回到点击链接的消息位置。
4. 补充 Compose UI 测试，覆盖返回键优先级、深色模式和 Markdown 表格布局。
5. 准备正式签名和 Release 构建流程后，再考虑公开分发。
