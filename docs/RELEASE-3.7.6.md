# Hermes Android 3.7.6 · 卡片表达、详情稳定性与连接恢复

## 这次针对什么

用户反馈首页和回看样式不同、分类按钮生硬、卡片缺乏上下文、上拉详情时持续跳动，以及连接仍频繁报错。录屏显示跳动出现在卡片详情窗口，内容与底部操作区一起位移；截图中的“网络连接不稳定”来自 IOException 的统一映射，不能仅凭这句提示判断为 WebSocket 故障。

## 视觉与阅读

- 首页复用回看的 GlassPanel：同一主题圆角、无描边、无阴影、不透明面板。分类按钮改为柔和填色，保留可点击范围及选中状态。
- 首页先显示标题和完整的简短背景，再显示问题与类型摘要。旧长摘要尽量取完整句子，不直接按字数截成半句；全文保留在详情。
- 普通决定卡选项放进详情，避免首页卡片过高。不同交互类型仍保留各自的信息表达。
- 真实卡片详情和卡片体验使用固定的全屏 Dialog 阅读窗口，顶部关闭、内容独立滚动、底部操作固定。移除旧的可拖拽 ModalBottomSheet 与百分比高度组合，消除该窗口的高度/锚点反馈路径。

## 内容、提示词与 Cron

旧版过于强调短文本，且 UI 可用 question 取代背景；已有 JSON 仍通过兼容路径展示，因此升级 APK 本身不会自动解决旧内容。

- 新规范要求每张卡交代明确对象、必要背景、现状及需要用户回应的一个问题。summary 通常 50–100 字、最多 160 字；不能为简短省掉主语和因果。
- 多个独立事项拆开；处理日志、缺哪些日报、写入结果进入 coverage_note / processing_notes；不靠归档推断当前目标，不编造统计口径或选项。
- 业务动作仍须有依据。脚本只能校验格式和部分明显缺陷，不能保证语义或事实正确。
- 持久 contract、writer、examples、Cron template 与本次 request.json 分离，避免把配置时的 Mode/日期带进之后每个 Cron 对话。
- 菜单“修正卡片与整理规则”会开启 Hermes 处理对话。它可整理现有 JSON、必要时查看有限的直接来源，并核对更新匹配的已有概览任务提示词。保留任务 ID、时间、时区、enabled、deliver、model/provider；不创建任务，不改其他任务或原业务记录。无法唯一匹配的任务跳过并报告。
- `editorial_version: 1` 启用背景摘要必填及明显处理说明标题检查；schema_version 1 与旧卡片继续兼容。任务完成必须回读验证，不能把请求已发送当作服务端更新成功。

安装后如已有卡片仍难懂，需要从首页右上角执行一次“修正卡片与整理规则”；仅安装不会改动用户服务器。

## 连接

- 普通 GET/HEAD 响应读取中途失败时，对瞬时断连/EOF/超时/DNS 问题最多增加一次独立的新连接读取。TLS 校验、取消和 HTTP 认证错误不在该重试范围。
- HTTP 写操作禁用自动传输重试；已发出的 RPC 也不重放。写入确认丢失时提示核对结果，避免重复任务或动作。
- Cookie 只在收到变更或过期时写加密存储，不在每个请求读取 Cookie 时反复加密落盘。
- 服务器在 gateway.ready 声明支持 heartbeat 时，使用 gateway.ping：15 秒周期，45 秒内任意有效入站消息视为存活。旧服务器不发不支持的探测，保留较宽松的协议 ping。RPC 默认等待 120 秒，审批响应 300 秒。
- 对照的公开实现：[官方连接管理](https://github.com/NousResearch/hermes-agent/blob/main/apps/shared/src/json-rpc-gateway.ts)、[官方请求与心跳通道](https://github.com/NousResearch/hermes-agent/blob/main/apps/shared/src/json-rpc-channel.ts)。核对日期 2026-10-03；不假定用户服务器已支持最新能力。
- 诊断页提供本次 App 运行中最近 12 条失败环节、时间与分类；不记录主机地址、Cookie、密码、查询参数、正文或文件路径，不上传。区分读取超时、DNS、安全连接、HTTP 状态及实时通道关闭。非当前页的会话列表补读失败不会弹全局错误覆盖卡片；实际请求错误仍可诊断。

这些处理改善已定位的客户端路径。没有用户手机现场日志或服务器访问，不能证明这就是所有故障的根因，也不能用模拟测试宣称真实移动网络已完全稳定。
