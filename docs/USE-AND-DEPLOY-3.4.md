# Hermes 3.4.0 预览版：安装与使用

这个版本从原始 3.2 开发，将此前讨论的四轮功能合并为一个版本。3.3 的独立 companion 服务、拆字待办和录音备忘系统没有被迁入。

## 这次可以怎样用

| 你的场景 | 手机上的操作 | 保存或执行的位置 |
| --- | --- | --- |
| 随口问一句、简单确认信息 | 首页“快问一句”；对话里可切换“快问 / 深入聊聊” | 原来的 Hermes Profile 和会话 |
| 路上刷到值得研究的内容 | 系统分享至 Hermes → “先收下” → 补一句关注点 | 当前项目工作目录的普通 Markdown 文件与附件 |
| 准备研究之前的素材 | 工作近况 → 资料 → 继续分析 | 原对话或新建的 Hermes 会话 |
| 工作多而杂，想理顺一天 | 工作近况 → 更新近期重点 → 安排今天 / 梳理本周 | Hermes 讨论草案，确认后的计划保存在工作目录 |
| 晚上复盘 | 工作近况 → 一起复盘；回复后“收下 / 跟进”→ 复盘 | 原会话和复盘记录 |
| 约定之后检查一件事 | “收下 / 跟进”→ 跟进 → 选择日期时间 → 保存 → 确认创建提醒 | Hermes 原生 Cron；手机镜像一条到时提醒 |
| 给团队整理指导材料 | 对话“收下 / 跟进”→ 整理成团队说明稿 → 收为交付成果 | Hermes 原会话与普通文件；分享时由你选择接收方式 |
| 不方便打字 | 对话麦克风录音 → 再点结束 → 检查文字 → 发送，或收为资料/跟进 | 录音暂存在手机；识别由当前 Hermes Profile 的 STT 完成 |

“人格化”体现在连续的背景、称呼和交流偏好，以及记得双方确认过的安排。工作近况里的“相处方式”可以写下你希望它怎样回答、怎样与你协作。偏好先保存，确认后用于手机发起的对话；不会自动覆盖服务器的 SOUL.md 或 MEMORY.md。

## 安装

安装 `Hermes-3.4.0-preview.apk`。应用 ID 为 `com.qingyu.hermescompanion.preview`，版本码 340，沿用附件里原有的预览版签名。签名与版本已通过本地构建工具检查，符合覆盖升级条件；这不等于已经在你的手机上完成升级实测。

不要先卸载旧版。卸载会清除手机本地的设置、未同步草稿和保留录音。服务器上的原会话和文件独立保留。

仍使用原来的 Hermes 网关地址、账号和密码。本版不需要启动另一个服务，也没有新增端口。

## 第一次打开，先做这几步

1. 在“回看”的项目视图中选择明确的项目工作目录。建议使用你日常梳理经营和个人安排的统一工作目录，把“AI 短视频”“私域获客”“生活”等作为资料主题。
2. 如果未选择项目，当前 Profile 需要有明确的绝对工作目录，或者 Hermes 原生项目中已经有活动项目。APP 不会擅自把服务器根目录当作工作台。
3. 首页打开“工作近况”，更新近期重点，并按实际情况确认采用。
4. 试着收下一条资料，然后刷新。没有“等待同步”提示才表示服务器写入及回读校验均已成功。单份上传失败不会阻塞其他资料；失败草稿可以编辑、移除有问题的附件后再同步。
5. 在“我的 → 语音设置”保存并测试当前 Profile 的 STT。建议先录一句短中文；识别成功后再用于日常输入。
6. 如需手机提醒，允许系统通知。跟进页面可打开“准确闹钟”的系统设置；未允许时使用系统允许的近似提醒。

## 规划不会替你做决定

“安排今天”“梳理本周”“一起复盘”会准备一条可编辑的请求，带入已经确认的重点和计划。你检查后发送，Hermes 才会处理。

回答可以收为计划，并选择“今日计划”“本周计划”或“单独一份”。未勾选确认时，它仍是草案。**新的草案不会顶掉此前已确认的安排**；点“确认采用”后才更新依据。

APP 不会把每句话自动拆成待办，不会因为生成了一份计划就创建定时任务，也不会把聊天里的建议显示成已完成工作。会议时间、业务数据和团队进度需要你提供，或由 Hermes 已配置的工具实际读取。

## 电脑和手机怎样接续

普通聊天继续使用同一个 Hermes 网关、Profile 和会话记录。“回到原对话”保留资料或成果的来源。

资料、重点、计划、复盘、成果和相处偏好保存为当前工作目录中的文件。文件名格式：

`hermes-assistant-<Profile 名称的 SHA-256 前 12 位>-<版本 UUID>.md`

附件使用 `hermes-material-...` 文件名。两端使用相同 Profile 和相同工作目录，才是在看同一份工作台。切换项目或 Profile 会切换近况范围，页面会显示当前范围。

不需要安装脚本就能阅读这些文件。源码中的 `tools/assistant_workspace.py` 是可选的电脑端读写工具，使用 Python 标准库，不启动服务、不调用模型、不管理 Cron。它让桌面 Hermes 能按相同版本规则增加或合并记录。

可在桌面 Hermes 中告诉它：

> 我的助理资料在当前工作目录的 hermes-assistant-*.md 文件中。请按当前 Profile 的文件前缀读取；记录之间的 entity 和 parents 表示版本关系。以已确认的内容为依据，遇到并发版本先和我确认。修改时写新版本，保留原文件。

若希望桌面 Hermes 自动记住这个位置，可明确让它使用原有的记忆能力记录位置与阅读约定。APP 不会假装已经替服务器完成永久记忆配置。

## 跟进与通知

保存跟进内容之后，仍需明确确认日期、时间和时区，APP 才调用 Hermes 原生 Cron。只有服务器返回对应任务，才显示创建已确认。

Hermes 到时执行跟进摘要，结果进入原有任务体系。手机的提示表示“约定时间到了”，不代表 Hermes 一定执行成功。执行状态和输出在“任务”中查看。

如果创建请求中断，APP 会先用同源标记查询，防止重复创建。无法核实的情况下会显示“结果待核对”，不会无限重发。取消操作针对确切的 Cron ID，同时取消本机镜像提醒。

后台通知受 Android 通知权限、准确闹钟授权、省电策略和厂商后台限制影响。电脑端取消或暂停提醒后，手机下一次成功刷新会同步；离线手机在未获知服务器变化前，可能仍发出之前已经约定的本机提示。原有 Cron 完成通知使用周期性检查，不承诺秒级到达。

## 语音失败之后

单次录音最长 5 分钟，使用 AAC/M4A。上传以流式 Base64 JSON 发送，限制 15 MB，不同时把原音频和完整编码副本堆在内存中。STT 请求明确绑定服务器、账号、Profile 和原会话。

- 上传或识别失败：录音保留，点击“重新识别”。
- 切到后台：停止当前单次录音并保留，回到原对话后可继续识别。
- 成功转写：文字写入原对话草稿，录音随后清理；文字不会自动发出。
- 切换了对话：文字回到原对话草稿，不插入正在看的另一段对话。
- 切换了账号或 Profile：结果先保留，回到原身份后恢复。
- 主动点“删除录音”：确认后删除未转写录音。
- 服务端返回 413：检查反向代理的请求体上限。15 MB 音频经过 Base64 后约为 20 MB，需要给 JSON 请求留出余量。
- 服务端返回 404/405/501：当前网关没有提供这条 STT 接口；可使用已配置的手机系统识别，或核实 Hermes 网关版本与语音配置。

系统杀死进程时，如果录音容器还没有正常结束，音频可能不完整；不能承诺恢复尚未成功结束的录音。连续语音模式保留原有停顿发送与朗读行为，和上述“单次录音先检查文字”分开。

## 这次没有替你接入的外部数据

没有直接接管抖音、视频号、企业微信、投放后台或公司的经营数据；也没有自动发送团队消息。分享视频链接只表示已收下链接，只有 Hermes 实际读取到内容后才能分析视频。研究、搜索、数据分析、模型和知识库访问继续取决于你服务器现有的配置与权限。

快问不切换全局模型：在网关支持且原思考设置可恢复时，临时降低本轮思考强度，结束后恢复。无法确认支持时沿用原设置。因此，回复速度仍受服务器、模型和网络影响。
