# 助理资料协议 v1

本协议只描述 Hermes 工作目录中的助理资料。聊天和任务执行仍使用 Hermes 原有会话及 Cron。这里没有第二套任务执行器或后端服务。

## 范围与文件

客户端缓存范围为服务器 URL、账号、Profile、工作目录四元组；文件使用 Profile 名称 SHA-256 的前 12 个十六进制字符作前缀。项目和 Profile 切换后不跨范围显示资料或提交写入。

- 记录：`hermes-assistant-<profile_hash12>-<revision_uuid>.md`
- 附件：`hermes-material-<revision_uuid>-<index>-<safe_name>`

使用已有工作目录，不调用未经验证的创建目录接口，也不假设服务器根目录可以作为用户工作台。

每份记录第一行是元数据，后续为纯文本或 Markdown：

```text
<!-- hermes-assistant-v1 {"schema":1,...} -->
正文
```

元数据包含：

| 字段 | 含义 |
| --- | --- |
| schema | 固定为 1；未知版本拒绝解释 |
| revision | 本次不可变版本 UUID |
| entity | 同一份逻辑内容的稳定 ID |
| parents | 此版本明确替代的旧版本 UUID 列表 |
| kind | MATERIAL / FOCUS / PLAN / REVIEW / FOLLOWUP / RESULT / PREFERENCES |
| title、intent、topic | 标题、关注点、主题 |
| source_session、source_message | 原会话与消息来源，可为空 |
| files | 已保存或明确引用的服务器附件路径 |
| created_at | 客户端创建时间，Unix 毫秒；不用于解决并发冲突 |
| confirmed、archived | 用户确认、收起状态；不是业务任务执行状态 |
| due_at、zone | 跟进的确切时间和时区 |
| cron_id | Hermes 返回的原生 Cron ID |
| reminder_attempted | 创建请求已经进入可能生效的阶段，需要查询确认后才能进一步处理 |

标题中的 `-->` 在 JSON 中转义为 `--\u003e`，避免提前关闭元数据行。

## 修改与确认

永远新增版本文件，不覆盖既有版本。有效的 `parents` 只能替代同一个 entity。没有被新版本引用的版本都是当前分支；两个端同时修改时保留两个分支。

合并时读取所有分支、整理内容，再新增一个明确引用这些分支的版本。移动端会提示并发版本；普通更新不会自动吞掉另一分支。

新计划、重点或偏好可以先作为未确认草案。对于只有一个当前分支的内容，客户端沿父版本寻找最近的已确认版本作为现行依据；直到用户确认新草案。并发分支不能自行选定依据，收起的内容不再提供现行依据。

日计划使用 `plan-YYYY-MM-DD`，周计划使用 `week-YYYY-MM-DD`（本周周一），近期重点使用 `focus`，相处方式使用 `preferences`。独立材料和成果使用各自 UUID。

## 写入与重试

1. 附件字节和记录先写入应用私有目录的持久化待同步区。
2. 附件先上传，随后上传记录。POST 使用不可变文件名及 `overwrite=false`。
3. 只有文件回读字节一致才确认同步成功。
4. POST 响应丢失后先回读目标文件；相同即确认，不同则不覆盖。
5. 单项失败保留其草稿，继续同步其他项。用户可以编辑失败草稿并移除有问题的附件；修订使用新的 UUID，并保留版本关系。
6. 服务端列表是在线权威；断网时显示明确标注的缓存。缓存不代表已获得最新服务端状态。

服务器手工修改旧文件不会产生新版本，且可能因不可变缓存而无法及时反映。电脑端应使用追加版本的方式；可选脚本提供这种写入方式。

## 原生提醒

创建前先保存 `reminder_attempted=true` 的版本。每次创建或核对都重新读取当前版本，拒绝并发分支，并在原生 Cron 中查询 `[hermes-assistant:<entity>]` 标记。

- 找到唯一对应任务：保存其 ID，确认已创建。
- 从未尝试，且时间在未来：发起一次创建。
- 曾尝试但查不到任务：保持未知状态，要求核对，不盲目再 POST。
- 找到多个对应任务：提示核对，不任意挑选。

创建 POST 关闭传输层自动重试。手机 AlarmManager 仅镜像已经确认的提醒；它不启动另一套 Agent，也不宣称执行完成。原生任务与手机提示的状态分开。

## 对话与单次语音

助理流程的简短请求放入可编辑输入框。参考资料、来源和版本约定单独保留为会话上下文；用户检查并发送后才调用 Hermes。

快问沿用现有模型。在原设置可恢复且服务端支持时，对单个运行会话临时减少思考强度，结束后恢复；不改全局模型。附件仍走原有附件流程。

单次录音使用应用私有文件，转写请求按明确的 Profile 发送。录音元数据绑定完整的服务器、账号、Profile、会话及设置测试用途。取消上传或切换范围不会把原录音误删，也不会把迟到结果插入新会话。文字草稿和录音回执原子提交，进程恢复后不会重复追加同一段转写。

## 当前依赖的接口

沿用 3.2 代码已有的接口及格式：

- `/api/config`、原生 projects RPC：确定明确工作目录。
- `/api/files`、`/api/files/read`、`/api/files/upload`：列举、读取、写入。
- `/api/cron/jobs` 及其单任务接口：原生定时任务。
- `/api/audio/transcribe`：`data_url` 与 `mime_type` 的 JSON 请求。
- 既有 JSON-RPC / WebSocket：会话、消息、附件、临时会话思考设置。

开发环境验证的是这些契约下的本地模拟网关联调。你的实际网关版本、权限、反向代理、STT 服务商与后台运行情况仍需实机联调确认。
